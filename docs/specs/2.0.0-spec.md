## 2. 조사 결과 (Alt 0.11.3, 2026-09-27)

출처는 `/Applications/Alt.app` 번들 코드와 공식 SDK 문서(`github.com/altalt-org/alt-plugin-sdk`, `llms.txt`)입니다.

### 2.1 Alt 플러그인 샌드박스
- 플러그인은 샌드박스 `WebContentsView` 안에서 돌아갑니다. Node, 파일시스템, 프로세스 실행이 없습니다.
- CSP가 `connect-src 'none'`이라 외부 네트워크가 막히고, 127.0.0.1도 차단됩니다.
- `alt.ai.*`로는 Alt 클라우드 모델과 로컬 모델만 쓸 수 있습니다. Alt 내장 Claude/Codex 연동은 플러그인에 열려 있지 않습니다.
- Alt UI에 버튼을 추가하는 API가 없습니다. 플러그인은 별도 창으로 뜹니다.

**결론**: Alt 플러그인 하나로는 옵시디언에 보내기와 CLI LLM 호출을 할 수 없습니다. 그래서 2.0은 옵시디언 플러그인을 중심에 둡니다(D1).

### 2.2 외부에서 Alt 데이터를 읽는 경로
| 경로 | 장점 | 한계 |
|---|---|---|
| 로컬 HTTP API `127.0.0.1:45623` | 앱 수준 추상화라 DB 스키마 변경에 덜 흔들림. `{ok, data}` 응답 | Alt가 실행 중이어야 함. Bearer 토큰은 `~/Library/Application Support/alt/http-server-token`(0600)에 있음. 공식 문서 없음 |
| SQLite `data/database/lecture_notes.db` | Alt가 꺼져 있어도 됨 | 스키마가 v12에서 v40까지 바뀌어 옴. 실행 중에는 잠겨 있어 복사해서 읽어야 함 |
| 공개 공유 URL (현행) | 이미 구현됨, 2026-09-27 기준 동작 | 타임스탬프 없음, 요약이 0자로 나옴, 공유 설정 필요 |

HTTP API 라우트는 코드로만 확인했고, 아직 실제로 호출해 보지 않았습니다(Alt가 꺼져 있었음).
- 주요 GET 라우트: `/api/lectureNotes`, `/api/lectureNotes/:id/components`, `/api/folders/tree`, `/api/noteComponents/note/:noteId`, `/api/events`(SSE).
- PDF는 파일 다운로드 라우트가 없어서 `file_metadata.file_path`로 디스크에서 직접 읽습니다.

### 2.3 데이터 형태
- **전사**: `[{createdAt, relativeStart, segments:[{start, end, text, speaker}]}]` 형태이고, 시간 단위는 ms입니다.
- **슬라이드**: PDF에서 추출한 텍스트가 들어 있고, 페이지 구분자는 없습니다.
- **요약/메모**: plate-json 형식입니다. HTTP API는 마크다운으로 변환해 줍니다.
- **슬라이드와 시간의 매핑은 없습니다.** `slide_memo.slideIndex`만 페이지와 연결됩니다.
- **로컬 노트 ID(UUIDv7)는 공개 URL ID와 매핑되지 않습니다.**

### 2.4 LLM CLI (이 Mac 기준)
| CLI | 버전 | 모델 선택 | effort 선택 | 이미지 입력 | 구조화 출력 |
|---|---|---|---|---|---|
| `claude` | 2.1.283 | `--model` | `--effort` | `--add-dir` 후 파일 경로를 Read | `-p --output-format json --json-schema` |
| `codex` | 0.155.1 | `-m` | `-c model_reasoning_effort=<level>` | `exec -i <FILE>` | `exec --output-schema <FILE> --json` |

Gemini/Antigravity CLI는 2.0에서 구현하지 않습니다(D6). 프로바이더 인터페이스만 열어 둡니다.


## 3. 목표와 비목표

### 목표
- **G1. API 키 없이 생성.** 사용자가 구독 중인 LLM CLI를 씁니다. 작업마다 프로바이더, 모델, effort를 고를 수 있습니다(D5).
- **G2. Alt 로컬 노트에서 바로 가져오기.** 옵시디언 사이드바에서 Alt 노트 목록을 고릅니다. URL 붙여넣기는 대체 경로로 남깁니다.
- **G3. 전사를 슬라이드에 정렬.** 전사 타임스탬프와 슬라이드 텍스트를 이용합니다. 균등 분할은 대체 경로로만 씁니다.
- **G4. 스킬과 플러그인 통합.** 같은 프롬프트 명세와 같은 해시 규칙을 씁니다.
- **G5. 시험 요약과 퀴즈를 검증 기능으로 교체.** 사용자 노트(노션)를 슬라이드·전사와 대조합니다.
- **G6. 폴더 구조 개편.** 영어 폴더명을 쓰고(D3), 1.x vault를 옮기는 마이그레이션 명령을 제공합니다.
- **G7. 건당 토큰을 합리적으로.** 5절의 기법을 적용해, 1.1.0 대비 강의당 입력 토큰을 절반 이하로 줄입니다. 이 목표치는 1단계 벤치마크 후 확정합니다.

### 비목표 (2.0 범위 밖)
- Alt 안의 "옵시디언으로 보내기" 버튼. 샌드박스 제약 때문에 2.x 이후에 검토합니다(4.4절).
- Gemini/Antigravity CLI 구현.
- 모바일 지원. `isDesktopOnly: true`를 유지합니다.
- Alt DB에 쓰기. 읽기만 합니다.

## 4. 설계

### 4.1 구성
```
Obsidian plugin (desktop)
├─ sources/
│  ├─ AltLocalApiSource      기본. HTTP API + 토큰 파일
│  ├─ AltLocalDbSource       Alt가 꺼져 있을 때. DB를 임시 폴더로 복사해 읽기 전용으로 사용
│  └─ AltPublicUrlSource     현행 스크래퍼, 대체 경로
├─ prep/                     LLM 없이 도는 결정적 전처리 (5.1절)
│  ├─ SlideAnalyzer          페이지 텍스트, 이미지 비중, 표지/목차 판별, 해시
│  ├─ TranscriptAligner      전사 세그먼트를 슬라이드에 배정
│  ├─ TranscriptCompressor   군말 제거, 반복 제거, 슬라이드별 상한
│  └─ TranscriptSections     슬라이드 없는 강의의 전사 구간 (4.10절)
├─ llm/
│  ├─ CliRunner              spawn 공통부: PATH 해석, 타임아웃, 취소, 사용량 수집
│  ├─ ClaudeCliProvider
│  ├─ CodexCliProvider
│  └─ (GeminiApiProvider, OllamaProvider는 2.0.0-beta.4에서 제거, D9)
├─ prompts/                  스킬과 공유하는 단일 프롬프트 명세 (md 파일)
├─ verify/NoteVerifier       사용자 노트 대조 검증
├─ budget/                   토큰 예측, 실제 사용량 기록
└─ vault/, ui/               현행 구조 유지·확장
```

모든 소스는 같은 `LectureBundle`을 반환합니다:
```ts
interface LectureBundle {
  sourceId: string;            // alt local UUID 또는 공개 URL id
  sourceKind: "alt-local" | "alt-url";
  title: string;
  lectureDate?: string;
  folderPath?: string[];       // Alt 폴더 트리. 과목 자동 추정에 사용
  pdf: ArrayBuffer | null;
  slideTexts: string[] | null; // 페이지별 텍스트. PDF에서 pdfjs로 추출
  transcript: TranscriptSegment[]; // {startMs, endMs, text, speaker}. URL 소스면 시간은 null
  summaryMarkdown?: string;
  memoMarkdown?: string;
}
```

### 4.2 LLM 선택과 CLI 규칙

#### 작업별 선택
설정 화면에서 작업마다 프로바이더, 모델, effort를 따로 고릅니다.

| 작업 | 기본 프로바이더 | 기본 모델 | 기본 effort | 이유 |
|---|---|---|---|---|
| 슬라이드 해설 | Claude CLI | 사용자 기본 모델 | medium | 품질이 가장 중요한 본 작업 |
| 개념 추출 | Claude CLI | 경량 모델 (예: Haiku) | low | 이미 만든 해설 요약에서 뽑으므로 가벼움 |
| 전사 정렬 확인 | 없음 (스크립트만) | | | 필요할 때만 경량 모델 |
| 노트 검증 | Claude CLI | 사용자 기본 모델 | medium | 판정 정확도가 중요 |

- 모델은 드롭다운으로 고릅니다. Claude는 별칭(`sonnet`, `opus`, `haiku`), Codex는 Codex가 스스로 저장한 모델 캐시(`~/.codex/models_cache.json`, 모델 호출 없음)의 공개 모델, 그리고 최근 쓴 값, "CLI 기본값", "직접 입력"(검사하는 입력칸)을 둡니다. 2.0.0-beta.4부터 표는 빈 값 대신 실제로 쓰는 모델과 effort를 보여주고, 프로바이더를 바꾸면 그 프로바이더의 작업 기본값을 넣습니다. 이전 저장값의 빈 모델과 effort는 한 번만 작업 기본값으로 채웁니다(설정 버전 3).
- 2.0.0-beta.5부터 모델은 버전과 id로 보여줍니다(`Opus 5.5 (claude-opus-5-5)`). 별칭의 "현재"는 실제 실행에서 기록한 값만 쓰고, 기록이 없으면 플러그인 표의 값을 기준일과 함께 보여줍니다. Claude 목록은 Claude Code가 저장한 모델 목록(`~/.claude/cache/model-catalog/*-cc.json`, 모델 호출 없음)에서, 없으면 플러그인에 넣어 둔 목록에서 읽고, 버전이 붙은 항목은 그 id를 그대로 `--model`에 넘깁니다. 별칭(`fable`, `opus`, `sonnet`, `haiku`)은 그대로 고를 수 있고 `opus (최신 Opus, 현재 Opus 5.5)`처럼 지금 가리키는 모델과 함께 보입니다. 실행마다 CLI 결과의 modelUsage에서 실제로 쓴 id를 읽어 플러그인 데이터(`resolvedModels`)에 남기고, 그 값이 "현재"와 설정의 "마지막 실행"이 됩니다. 저장된 별칭은 바꾸지 않습니다(작업 기본값도 별칭 그대로). effort 목록은 모델이 지원하는 단계만 보여줍니다(Claude Code 목록의 effort_options, Codex 모델 캐시).
- **실행할 때 고르기 (2.0.0-beta.5)**: 사이드바의 가져오기 예상 사용량 패널(해설·요약, 개념 추출)과 노트 검증 예상 사용량 패널(판정)에서 그 실행의 프로바이더, 모델, effort를 바꿀 수 있습니다. 예상치는 그 선택으로 다시 계산하고(5.5절), 설정은 "기본값으로 저장"을 눌러야만 바뀝니다. 진행 패널과 노트의 `alt2obs_usage`(`model`, `effort`, `concept_model`)에는 CLI가 실제로 쓴 모델을 적습니다.
- effort 값은 CLI별로 매핑합니다.
  - Claude: `--effort <level>`
  - Codex: `-c model_reasoning_effort=<level>`
- 프리셋 두 개를 제공합니다.
  - `절약`: 모든 작업에 경량 모델과 low effort
  - `품질`: 해설과 검증에 상위 모델과 high effort

#### 실행 규칙
1. **실행 파일 경로.** Dock으로 실행한 옵시디언은 셸 PATH를 물려받지 않고, nvm 경로도 보이지 않습니다. 다음 순서로 찾습니다.
   - 설정에 적은 절대 경로
   - 로그인 셸에서 `command -v`로 한 번 조회해 캐시한 경로
   - 둘 다 실패하면 설정 화면에 안내를 띄움
2. **셸 문자열을 조립하지 않습니다.** `spawn(bin, argsArray)`만 쓰고, 프롬프트는 stdin이나 임시 파일로 넘깁니다.
3. **기본 컨텍스트를 최소로 둡니다.** CLI가 기본으로 싣는 도구 정의와 프로젝트 설정도 토큰이기 때문입니다(5.4절).
   - Claude: `--tools`로 Read만 허용하고 `--no-session-persistence`를 붙입니다. `--add-dir`은 작업 임시 폴더만 지정합니다. 작업 폴더를 vault 밖 임시 폴더로 두어 CLAUDE.md 같은 프로젝트 설정이 끼어들지 않게 합니다.
   - Codex: `--sandbox read-only`로 실행하고, 작업 폴더를 같은 임시 폴더로 둡니다.
   - 어느 쪽도 vault에 직접 쓰지 않습니다. 쓰기는 플러그인이 합니다.
4. **구조화 출력.** 결과는 JSON 스키마로 강제합니다. 검증에 실패하면 실패한 항목만 다시 요청합니다.
5. **진행, 취소, 타임아웃.**
   - 진행 상황을 사이드바에 표시합니다.
   - 취소하면 자식 프로세스 그룹을 종료합니다.
   - 호출당 기본 타임아웃은 300초입니다.
   - 부분 결과는 1.x와 같은 `⚠️ 처리 실패 슬라이드` 규칙으로 저장합니다.
6. **사용량 고지.** 설정 화면과 README에 "사용자 구독 한도를 소모한다"는 점과 외부 프로세스를 실행한다는 점을 적습니다.

### 4.3 전사 정렬 (TranscriptAligner)
1. 슬라이드 텍스트와 전사 세그먼트를 정규화합니다. 소문자화, 공백 정리, 불용어 제거를 합니다.
2. 슬라이드 순서는 대체로 단조 증가한다고 가정합니다. 동적 계획법으로 세그먼트 구간을 나누고, 점수는 BM25 계열 토큰 겹침으로 매깁니다.
3. 신뢰도가 낮은 구간만 모델에 확인을 맡깁니다(선택 설정).
   - 세그먼트 묶음과 후보 슬라이드 2~3장의 텍스트만 보냅니다. 이미지는 보내지 않습니다.
   - 판정은 4.2절 설정의 경량 모델이 합니다.
4. 결과 `slideIndex -> [startMs, endMs]`를 노트 frontmatter(`alt_alignment`)에 저장합니다. Synced Viewer가 이 값을 씁니다.
5. 타임스탬프가 없는 URL 소스는 현행 균등 분할을 씁니다.
6. 정렬은 켜고 끄는 옵션이 아닙니다. 스크립트만으로 돌아 토큰이 들지 않고 항상 균등 분할보다 낫기 때문에, 타임스탬프가 있으면 늘 적용합니다. 가져오기 화면에는 적용 여부만 표시합니다.

수락 기준: 수동으로 정답을 매긴 강의 2개에서 슬라이드 배정 정확도가 균등 분할보다 높아야 합니다. 목표는 80% 이상입니다.

### 4.4 Alt 다리 플러그인 (2.0 범위 밖, 기록용)

### 4.6 노트 검증 (NoteVerifier)

#### 입력 (D2 확정)
- **기본**: 노션 페이지를 마크다운으로 내보내 vault에 둔 파일을 고릅니다.
- **선택: Notion MCP.** 노션 페이지 URL을 넣으면, 사용자의 Claude CLI(또는 Codex)에 설정된 Notion MCP로 가져옵니다.
  - 이 호출에는 Notion 조회 도구 하나만 허용합니다.
  - 모델에는 요약하지 말고 원문 마크다운만 반환하라고 지시합니다. 가져오기에 드는 토큰을 줄이기 위해서입니다.
  - 가져온 원문은 vault 밖 캐시에 `last_edited_time`과 함께 저장하고, 페이지가 바뀌지 않았으면 다시 가져오지 않습니다.
  - MCP가 설정돼 있지 않으면 설정 방법을 안내하고, 기본 경로를 쓰도록 합니다.
- **붙여넣기**도 허용합니다.

#### 처리
1. **주장 분해 (스크립트).** 사용자 노트를 문장과 불릿 단위로 나눕니다. 제목, 빈 줄, 링크만 있는 줄은 버립니다.
2. **근거 검색 (스크립트).** 주장마다 BM25로 근거 후보를 뽑습니다.
   - 슬라이드 텍스트에서 상위 2개를 뽑습니다. 1차 근거입니다.
   - 정렬된 전사 구간에서 상위 2개를 뽑습니다. 2차 근거입니다.
   - 근거 점수가 매우 높고 숫자·수식이 없는 주장은 `맞음 후보`로 표시해 LLM 판정 묶음에서 뒤로 보냅니다.
3. **판정 (LLM, 배치).** 주장 20개와 각자의 근거 조각만 한 번에 보냅니다. 판정은 네 가지 중 하나입니다.
   - `맞음`
   - `틀림`
   - `근거 없음`
   - `전사 불확실`: STT 오인식이 의심되는 경우
4. **누락 탐지 (스크립트 + LLM 1회).**
   - 슬라이드 중 어떤 주장과도 연결되지 않은 것을 모읍니다.
   - 그 슬라이드의 제목과 핵심 문장만 보내 `누락 후보`를 고르게 합니다.

#### 출력
- `Verification/<lecture> verification.md`에 씁니다.
- 각 항목에는 원문 인용, 판정, 근거 링크를 답니다. 근거 링크는 슬라이드 앵커 `[[<lecture>#📚 슬라이드 12]]`와 전사 시각 `[mm:ss]`입니다.
- 사용자 노트 원본은 수정하지 않습니다.

#### 수락 기준
틀린 문장을 일부러 5개 섞은 노트에서 4개 이상을 `틀림`으로 잡아야 합니다. 맞는 문장을 `틀림`으로 판정하는 오탐은 1개 이하여야 합니다.

### 4.7 스킬과 배포판 통합
- **`prompts/*.md`가 단일 원본입니다.** 대상은 슬라이드 해설, 전체 요약, 개념 추출, 검증 프롬프트입니다.
  - 플러그인은 빌드할 때 이 파일들을 문자열로 포함합니다.
  - 스킬은 같은 파일을 읽도록 참조합니다.
- **스킬 설치 방식을 바꿉니다.**
  - `~/.claude/skills/alt2obs/SKILL.md`를 복사본 대신 저장소 `scripts/phase2/SKILL.md`로 향하는 심볼릭 링크로 바꿉니다.
  - 절대 경로 `/Users/biqnt/dev_project/...` 하드코딩을 제거합니다.
- **스킬도 결정적 전처리를 공유합니다.** `prep/`을 Node 스크립트로도 실행할 수 있게 만듭니다(`scripts/alt2obs-prep.mjs`). 그러면 스킬 경로도 5절의 토큰 절약을 그대로 누립니다.
- **슬라이드 해시를 통일합니다.**
  - 1.x: 플러그인은 `sha1(PNG 바이트)`, 스킬은 `sha1(noteId:page)`를 썼습니다.
  - 변경: 둘 다 `sha1(정규화한 페이지 텍스트)`의 앞 8자리를 씁니다. 정규화는 NFC, 소문자화, 모든 공백 제거입니다. 구현은 `src/core/slideHash.ts` 하나이고, 스킬은 `scripts/phase2/slide-hashes.mjs`로 같은 코드를 실행합니다.
  - 해시에 페이지 번호를 넣지 않습니다. 번호가 들어가면 슬라이드 하나를 앞에 끼워 넣거나 빼는 순간 뒤쪽 해시가 전부 바뀌고, 병합이 번호 기준(N-match)으로 짝을 지어 메모가 엉뚱한 슬라이드로 옮겨갑니다.
  - 텍스트가 같은 페이지(애니메이션 단계)는 해시가 같습니다. 병합은 같은 해시를 덱 순서대로 짝짓고 마커는 번호와 해시를 함께 쓰므로 안전합니다. `dup:N` 접미사는 쓰지 않습니다.
  - 텍스트가 없는 페이지(이미지 전용, 또는 텍스트 추출 실패)는 `sha1(sourceId + ":" + page)`로 대체합니다. 이 페이지만은 위치 기반이라 앞쪽에 슬라이드가 끼면 drift로 잡힙니다.
  - 1.x 노트는 첫 재가져오기 때 drift가 한 번 뜨지만, 메모는 기존 N-match 경로로 보존됩니다.

### 4.9 Synced Viewer
- 정렬 결과(`alt_alignment`)가 있으면 스크롤 위치를 비율 대신 슬라이드 앵커 기준으로 동기화합니다.
- 전사 패널을 추가합니다(선택). 현재 슬라이드 구간의 전사를 타임스탬프와 함께 보여줍니다.
- 슬라이드가 있는 강의를 가져오면 Synced Viewer로 엽니다(2.0.0-beta.4).
- 강의 PDF(같은 폴더에 `<이름>.md` 강의 노트가 있는 `<이름>.pdf`/`.PDF`; 강의 노트는 Alt id나 플러그인 출처가 frontmatter에 있거나 슬라이드 표식이 있는 노트)를 Obsidian의 PDF 보기로 열면 그 탭을 Synced Viewer로 바꿉니다(2.0.0-beta.5, 설정 "강의 PDF를 열면 뷰어로 열기", 기본 켬). 같은 쌍의 뷰어가 열려 있으면 그 탭을 보여주고, PDF를 연 탭은 뒤로 가기로 이전 화면으로 돌리며 뒤로 갈 곳이 없을 때만 닫습니다. 뷰어로 바꿀 때 PDF는 탭 기록에 남기지 않습니다. 뷰어의 "PDF만 보기"로 연 탭과 Obsidian을 켤 때나 설정을 켤 때 열려 있던 PDF 탭은 바꾸지 않고, 강의 노트(.md)를 여는 것도 바꾸지 않습니다. 뷰어는 PDF를 직접 그려 PDF 탭을 열지 않으므로 되돌림 반복이 없고, 같은 파일의 전환이 진행 중이면 두 번째 전환은 하지 않습니다(`src/ui/pdfOpen.ts`). 동기화는 두 창의 스크롤 이벤트로 합니다. 창 높이의 4분의 1 지점 위에 있는 마지막 페이지나 `## 📚 슬라이드 N` 제목을 현재 슬라이드로 보고, 150ms 머문 뒤 다른 창을 그 위치로 옮깁니다. 뷰어가 직접 시작한 스크롤은 끝날 때까지(scrollend) 되돌려 동기화하지 않습니다.
- 관리 주석 숨기기(기본 켬): Live Preview에서는 CodeMirror 6 확장이 `<!-- alt2obs... -->` 한 줄 주석을 감춥니다. 커서나 선택이 그 줄 또는 바로 위아래 줄에 닿으면 이어진 관리 줄 묶음 전체를 보여주고, 감춘 줄과 앞뒤 줄바꿈에는 사용자 입력이 들어가지 않게 막습니다(changeFilter). Synced Viewer는 렌더링 전에 그 줄을 빈 줄로 바꿉니다. 노트를 다시 그리거나 다시 가져올 때는 그 창을 잠시 잠가 두고 보던 위치를 되돌린 뒤 풉니다. 노트 내용과 `src/core/merge.ts`가 읽는 표식 문법은 바꾸지 않습니다. 메타 주석의 128자리 이미지 신호는 줄이지 않았습니다. 다시 가져올 때 이 값이 같아야 기존 해설을 재사용하므로, 표기를 바꾸면 2.0.0-beta.3 노트가 한 번 모두 다시 생성되기 때문입니다.

### 4.10 슬라이드 없는 강의 (4단계, 2.0.0-beta.6)
이번 학기 Alt 노트는 녹음과 시각이 있는 전사만 있고 슬라이드가 없는 경우가 많습니다. Alt의 "노트 추가"에서 고르는 종류(`lecture_notes.type`)가 `note`(노트)이면 녹음과 전사만 담고 Alt에서 슬라이드를 붙일 수 없습니다. `slide`(슬라이드)는 Alt에서 슬라이드를 붙일 수 있지만 아직 붙이지 않았을 수 있습니다. 예전 노트는 `legacy`입니다. 2.0.0-beta.5까지는 이런 강의를 강의 단위 노트로 만들었고 노트 검증은 거부했습니다. 4단계에서 정한 내용은 다음과 같습니다(D12).

#### 종류 판별 (`src/core/noteStatus.ts`)
| 종류 | 조건 | 사이드바 표시 | 할 수 있는 일 |
|---|---|---|---|
| 슬라이드 | Alt에 슬라이드 PDF가 있음 | 슬라이드 | 지금까지와 같은 슬라이드 경로 |
| 첨부 PDF | 플러그인에서 첨부한 PDF가 노트 옆에 있음 | 슬라이드(PDF 첨부) | 슬라이드 경로, 첨부한 PDF 사용. Alt에도 슬라이드가 있으면 "Alt 슬라이드로 바꾸기", 언제나 "첨부 해제" |
| 저장된 PDF | Alt에 지금 슬라이드가 없지만 슬라이드 노트 옆에 예전 가져오기가 저장한 PDF가 있음 | 슬라이드(저장된 PDF) | 슬라이드 경로, 그 사본 사용 |
| 슬라이드 미첨부 | type `slide`, 슬라이드 없음 | 슬라이드(미첨부) | Alt에서 슬라이드를 붙인 뒤 새로고침(먼저 안내), PDF 첨부, 요약 노트 만들기 |
| 전사만 | type `note`, 또는 `legacy`나 URL 노트에 PDF 없음 | 노트(전사만) | 요약 노트 만들기(기본), PDF 첨부 |
| 내용 없음 | 슬라이드도 전사도 없음 | 노트(전사 없음) | Alt 요약과 메모로 강의 노트 |

- PDF가 없는데 사용자가 "요약 노트 만들기"를 고르지 않았으면 가져오기는 토큰을 쓰기 전에 멈추고(`MissingPdfError`) 같은 선택지를 보여줍니다. 슬라이드 없는 노트로 조용히 넘어가는 일은 없습니다. URL 가져오기도 같습니다. URL PDF를 내려받지 못했으면 그 오류를 알리고 "다시 시도"를 먼저 보여주며, 공유 페이지를 일부만 읽었을 때도 먼저 묻습니다.
- "요약 노트 만들기"를 고르면 PDF는 쓰지 않습니다. 슬라이드 노트가 이미 있으면(또는 요약 노트인데 지금 전사가 없으면) 토큰을 쓰기 전에 거부합니다.
- 동기화된 슬라이드 파일이 아직 이 컴퓨터에 없으면 Alt에서 한 번 열어 내려받은 뒤 새로고침하라고 안내합니다. 노트 옆에 예전에 저장한 PDF가 있으면 그 사본으로 가져옵니다.

#### PDF 첨부
- 보관함의 PDF(퍼지 검색)나 컴퓨터의 파일(파일 입력으로 고른 파일을 ArrayBuffer로 읽음. 사라질 예정인 `File.path`는 쓰지 않음)을 고릅니다. 파일 앞부분에 `%PDF-`가 있는지 확인하고 강의 노트 옆 `<Subject>/Lectures/<lecture>.pdf`로 복사합니다. 노트가 이미 있으면 frontmatter에 `alt_pdf_source: "attached"` 한 줄만 넣습니다(`src/core/pdfAttach.ts`, `src/ui/attachPdf.ts`, `attachPdf` in `src/main.ts`).
- 이후 가져오기는 그 PDF를 슬라이드로 씁니다(전사 정렬, 슬라이드별 해설, Synced Viewer, 슬라이드 대조 검증). PDF는 이 순서로 고르고 읽을 수 없는 것은 건너뜁니다: 첨부한 PDF(노트에 표시가 있거나, 아직 노트가 없는데 노트 자리 옆에 있는 PDF), Alt의 PDF, 요약 노트가 아닌 노트 옆에 예전 가져오기가 저장한 사본(표시는 넣지 않음). 첨부한 PDF가 Alt의 PDF를 이기면 예상 사용량에 적습니다. 표시는 메타데이터 캐시가 아니라 노트 글에서 읽습니다. 첨부할 수 있는 파일은 300 MB까지입니다.
- "Alt 슬라이드로 바꾸기"는 노트에서 `alt_pdf_source` 줄만 지워 다음 가져오기가 Alt의 PDF를 쓰게 하고, "첨부 해제"는 그 줄을 지웁니다. 플러그인이 사본을 만들 때마다 경로, 크기, SHA-1을 플러그인 데이터(`attachedCopies`)에 남기고, 보관함의 이름 바꾸기와 옮기기를 따라 경로를 고치며, 없어진 파일의 기록은 지웁니다. 둘 다 기록과 크기, SHA-1이 같은 사본만 `vault.trash(file, true)`(시스템 휴지통, 안 되면 보관함의 .trash)로 옮기며 영구 삭제하지 않습니다. 그 밖의 파일(노트 옆에 원래 있던 보관함 파일을 그대로 첨부한 경우, 옮겨 온 사용자 파일, 사용자가 바꾼 사본, 예전 개발판의 `attachedInPlace`에 적힌 파일)은 사용자 파일로 보고 지우지 않습니다: 첨부 해제는 그대로 두고, Alt 슬라이드로 바꾸기는 다음 가져오기가 덮어쓰지 않도록 `<강의> (첨부한 PDF).pdf`(이미 있으면 번호를 붙인 이름)로 이름을 바꿉니다. 확인 창이 어느 경우인지 말합니다. 다시 가져올 때도 `alt_pdf_source: "attached"`는 frontmatter에 남습니다(`preservedFrontmatterLines`, 스킬은 `carry-frontmatter.mjs`).
- 이미 만든 요약 노트에도 첨부할 수 있습니다(사이드바 버튼, 명령 "Attach lecture PDF to the current lecture note"). 다음 가져오기에서 슬라이드 노트로 바뀌고, 예전 요약 노트 전체(구간 요약, 내 메모, 직접 쓴 글)는 1.0.x 노트와 같은 규칙으로 맨 아래 `## 이전 노트 백업`에 남습니다. 업데이트 확인 창이 그렇게 알려줍니다.

#### 요약 노트 (`src/pipeline/transcriptPlan.ts`, `transcriptPipeline.ts`, `src/generator/SectionSummaryGenerator.ts`)
1. 스크립트(토큰 0, `src/core/prep/TranscriptSections.ts`): 전사를 세그먼트 경계에서 말한 시간 기준 9~15분(목표 12분) 구간으로 나눕니다(1분 넘게 쉰 시간은 1분으로 셈. 녹음을 켜 둔 쉬는 시간 앞에 몇 초짜리 구간이 생기지 않게 함). 그 범위 안에서 앞뒤 2분의 낱말 겹침이 가장 적은 곳(주제가 바뀌는 곳)을 고르고, 쉬는 시간이 있으면 가산점을, 12분에서 멀면 감점을 줍니다. 남은 길이가 한 구간과 짧은 구간 사이면 반으로 나눕니다. 2시간 강의는 8~10개입니다. 시각이 없는 URL 전사는 문장 단위 조각(600자 이하)으로 자른 뒤 약 4,000자씩 나눕니다(공유 페이지는 전사를 한 줄로 이어 줌). 구간마다 군말, 반복, 두 번 받아 적은 문장을 지우고 1분마다 `[mm:ss]` 줄로 묶으며 3,000자까지 남깁니다(구간에 자주 나오는 낱말을 많이 가진 문장 우선).
2. 묶음 LLM 호출: 한 호출에 구간 12개, 전사 36,000자까지 보냅니다(2시간 강의는 1회). 앞부분은 늘 같은 지시문(`prompts/transcript-section-batch.system.md`)과 강의 공통 맥락이라 프롬프트 캐시에 걸립니다. 구간마다 300~900자 요약(개조식 불릿, 불릿 끝에 그 내용이 나온 `[mm:ss]`, definition/example/important callout, 학술 용어는 영어, 개념 링크는 `English (한국어)`)과 60자 이내 요지를 JSON으로 받습니다.
3. 전체 요약과 개념은 슬라이드 경로처럼 구간 요지로 만듭니다(map-reduce, `overview-from-sections.md`, `concept-extraction-sections.md`). 호출 수는 구간 묶음 수 + 2입니다.
4. 예산 미리보기(같은 프롬프트로 계산), 진행, 취소, 사용량 기록, 빠진 구간만 한 번 다시 요청, 연속 실패와 사용 한도에서 중단, 실패한 구간은 예전 요약 유지는 슬라이드 경로와 같은 코드입니다.

#### 노트 구조와 표식 (`src/core/sections.ts`)
- frontmatter: `alt_kind: "transcript"`, `section_count`. `alt_alignment`와 PDF는 없습니다.
- `## 📋 전체 요약` 블록 아래 구간마다 `## ⏱ 구간 N [mm:ss~mm:ss]` 제목, `<!-- alt2obs:section:N hash:H start -->` 요약과 요지 메타(슬라이드 메타 문법, 이미지 신호 없음) `<!-- alt2obs:section:N hash:H end -->`, 그 아래 표식 밖에 `> [!note] 내 메모`가 옵니다. 제목의 범위는 물결표로 씁니다.
- 해시는 구간 원문 전사에 4.7절 해시 규칙을 적용한 값입니다. 다시 가져올 때 해시와 시작 시각(초)이 같고 요지가 있는 구간은 요약을 그대로 쓰고(호출 없음, 설정 "바뀐 슬라이드만 다시 생성". 요약이 시각을 인용하므로 시작 시각도 봄), 바뀐 구간만 만듭니다.
- 노트를 처음 쓴 그대로 다시 가져오면 파일이 한 바이트도 바뀌지 않습니다(슬라이드 노트도 같음). CRLF로 저장된 노트도 LF로 바꿔 병합하고, 원래 줄 끝(CRLF)으로 다시 씁니다. '처리 실패' 목록은 `<!-- alt2obs:failures start|end -->` 사이에 두어 다시 가져올 때 새 목록으로 바꿉니다(슬라이드 노트도 같음).
- 병합(`src/core/merge.ts`): 해시, 그다음 시간이 가장 많이 겹치는 구간(짧은 쪽의 절반 이상), 그다음 번호 순서로 메모를 옮기고, 사라진 구간의 메모는 `## 🗑️ 사라진 구간 (orphan)`으로 옮깁니다. 다만 두 옛 구간이 새 구간 하나로 합쳐져 짝을 못 찾은 쪽은(그 시간의 절반 이상을 새 구간이 덮음) 메모를 `이전 구간 N [..]의 메모` 표시와 함께 그 새 구간 아래에 붙입니다. 구간 제목은 그 구간의 표식 바로 앞에 있는 같은 번호의 `## ⏱ 구간 N` 줄이고, 메모 칸은 다음 구간 제목까지입니다. 그래서 제목의 시각 뒤에 덧붙인 글, 제목 아래 글, 메모 안의 제목처럼 보이는 줄, 끝 표식이 지워진 구간의 글이 제자리에 남습니다(끝 표식이 지워진 구간에서 플러그인이 쓴 표식, 메타, 다시 쓰는 구간의 기본 제목 줄만 뺌). 이전 노트 백업에서 예전 frontmatter는 YAML 코드 블록으로 둡니다. 2.0.0-beta.5까지 만든 강의 단위 노트는 통째로 `## 이전 노트 백업`에 둡니다. 슬라이드 노트나 요약 노트를 단일 블록 노트로 덮어쓰는 일은 거부합니다. 슬라이드 표식 문법은 바뀌지 않았고, 스킬의 `merge-note.mjs`도 같은 코드입니다.

#### 노트 검증
슬라이드가 없는 강의는 전사 구간이 근거입니다. 노트의 구간 제목에서 시각을 읽어(제목이 없으면 가져오기와 같은 방식으로 나눔) 구간별 전사에 BM25와 용어표로 근거를 찾고, 근거마다 가장 잘 맞는 전사 조각과 그 시각을 붙여 `구간 N [mm:ss]`로 보냅니다. 판정 지시문(`prompts/note-verify-transcript.system.md`)은 근거가 음성 인식뿐이므로 관련 말이 깨져 있으면 `틀림`보다 `전사 불확실`을 고르라고 적습니다. 누락 확인은 이어지지 않은 구간을 요지와 함께 보냅니다. 결과 링크는 `[[<노트 경로>#⏱ 구간 N ...|<강의> · 구간 N]] [mm:ss]`입니다. 링크 대상은 옵시디언이 제목 링크를 맞출 때 지우는 문자(`[`, `]`, `:` 등)를 빼고 공백으로 바꾼 제목입니다(옵시디언 1.14.4 앱 코드의 stripHeading 확인). URL로 가져온 전사에는 시각이 없어 검증할 수 없습니다. 슬라이드 경로는 바뀌지 않았습니다.

#### Synced Viewer
슬라이드가 없는 노트에는 뷰어가 없습니다. 사이드바의 "뷰어로 열기"와 명령은 이유를 알려주고 "PDF 첨부"를 제안합니다. 요약 노트 옆에 첨부한 PDF는 노트가 슬라이드 노트로 바뀔 때까지 일반 PDF로 열립니다(4.9절의 전환에서 제외).

#### 스킬
`scripts/phase2/transcript-note.mjs`가 같은 구간 나누기, 같은 프롬프트, 같은 답 검사, 같은 노트 조립을 하고, `verify-prep.mjs`는 PDF 자리에 `-`를 받아 같은 방식으로 검증합니다. SKILL.md는 Alt 노트 종류에 따라 같은 선택지를 따릅니다(첨부는 PDF를 노트 옆에 복사하고 `alt_pdf_source: "attached"`를 넣은 뒤 슬라이드 경로).

#### 실제 확인 (2026-10-06, Claude Code 2.1.291, `sonnet` low)
CSED5 6강(type `note`, 75분, 전사 19,168자)을 구간 6개, 묶음 1개로 나눠 13,236자를 보냈습니다. 호출 3회(구간 요약, 전체 요약, 개념), 입력 12,454 토큰(예상 13,015), 출력 4,429 토큰(예상 6,681), 35초였습니다. 모든 구간에 `[mm:ss]`가 붙은 요약이 나왔고 개념 5개가 `English (한국어)` 이름으로 나왔습니다. CSED423 L9(type `slide`, 슬라이드 미첨부)는 63분에 전사가 2,409자뿐이라 확인 대상으로 쓰지 않았습니다.

## 5. 토큰 효율 설계

### 5.0 원칙
**스크립트가 할 수 있는 일은 스크립트가 하고, 모델에는 판단이 필요한 최소 입력만 보냅니다.** 모든 작업은 네 단계를 거칩니다.

```
[결정적 전처리]  →  [예산 산정·미리보기]  →  [배치 LLM 호출]  →  [결정적 후처리·검증]
 토큰 0              사용자 확인               캐시 친화 순서         토큰 0
```

### 5.1 결정적 전처리 (토큰 0)
- **SlideAnalyzer** (페이지별 계산):
  - `textChars`: pdfjs 텍스트 길이
  - `imageRatio`: 렌더링한 이미지에서 텍스트 영역을 뺀 비중
  - `kind`: `cover` / `toc` / `thanks` / `content` / `visual`
    - 판별 규칙: 첫·마지막 페이지 위치, "Contents", "Q&A", "Thank you" 같은 키워드, 텍스트 길이
  - `hash`: 4.7절 규칙
- **비실질 슬라이드는 LLM에 보내지 않습니다.** `cover`, `toc`, `thanks`는 템플릿 한 줄로 채웁니다.
- **중복 슬라이드를 묶습니다.** 애니메이션 단계처럼 텍스트가 거의 같은 연속 페이지(유사도 0.9 이상)는 마지막 페이지만 해설합니다. 앞 페이지에는 "다음 슬라이드와 같은 내용" 한 줄과 링크를 넣습니다.
- **TranscriptCompressor** (슬라이드별 전사 조각에 적용):
  - 군말("음", "어", "그러니까", "um", "uh")과 반복 구절을 제거합니다.
  - STT가 같은 문장을 두 번 낸 경우를 없앱니다.
  - 슬라이드 텍스트와 겹침 점수가 높은 문장을 우선해 슬라이드당 상한(기본 600자)까지만 남깁니다.

### 5.2 텍스트 우선, 이미지는 필요할 때만
이미지 한 장은 텍스트보다 훨씬 많은 입력 토큰을 씁니다.
- **텍스트만 보내는 경우**: `kind = content`이고 `textChars`가 충분하며 `imageRatio`가 낮은 슬라이드입니다.
- **이미지를 함께 보내는 경우**: `visual` 슬라이드(도표, 회로도, 그래프)와 텍스트 레이어가 없는 스캔 PDF입니다.
- **보낼 때는 해상도를 제한합니다.** 긴 변 1024px, PNG 대신 품질 80의 JPEG을 씁니다.
- 1단계 벤치마크에서 텍스트만으로 만든 해설이 품질 기준을 못 넘는 유형이 나오면 판별 규칙을 조정합니다.

### 5.3 배치와 캐시 친화 순서
- **배치.** 슬라이드마다 CLI를 띄우지 않고 한 번에 K장을 보냅니다. 기본 K=8이고, 이미지가 섞인 배치는 K=4입니다.
  - CLI 프로세스를 띄울 때마다 드는 고정 비용(시스템 프롬프트, 도구 정의)을 여러 슬라이드가 나눠 냅니다.
- **캐시 친화 순서.** 모든 배치 호출의 앞부분을 바이트 단위로 똑같이 둡니다.
  1. 고정 지시문 (`prompts/*.md`)
  2. 강의 공통 맥락: 제목, 과목 태그 목록, 이 강의 슬라이드 제목 목록
  3. 여기부터 배치마다 다른 내용: 슬라이드 텍스트, 압축 전사, 이미지
  - 이렇게 하면 두 번째 배치부터 앞부분이 프롬프트 캐시에 걸립니다. 캐시 적중률은 CLI 사용량 출력으로 측정해 벤치마크에 기록합니다.
- **출력 최소화.**
  - JSON 키를 짧게 두고, 필요한 필드만 요청합니다.
  - 슬라이드별 분량 상한을 둡니다. 기본 200~500자이고 `visual`은 700자까지 허용합니다.
  - 해설과 함께 슬라이드당 한 줄 요약(`gist`, 60자 이내)을 받습니다.

### 5.4 재사용과 재계산 회피
- **전체 요약은 map-reduce로 만듭니다.** 전사 전체를 다시 읽지 않고, 배치에서 받은 `gist` 목록과 Alt 요약으로 만듭니다.
- **개념 노트 이름 (2.0.0-beta.5)**: 문장 속 학술 용어와 개념 이름은 영어 원어로 쓰고(일반 낱말은 한국어), 새 개념 노트는 `English (한국어)`로 이름 붙입니다(예: `Lottery Scheduling (로터리 스케줄링)`). 예전 `한국어 (English)` 노트는 이름을 바꾸지 않습니다. 두 이름은 영어 부분이 같거나, 한국어 부분이 같고 영어 부분이 분명히 다르지 않으면(같은 낱말이거나 끝에 s, es, ing, ed, d만 붙은 꼴: Context Switch와 Context Switching. Process와 Processor는 다른 낱말) 같은 개념이고(대소문자, 공백, `_`, `-`, 파일 이름에 못 쓰는 문자, 끝의 마침표 무시. `Latency (지연)`과 `Delay (지연)`은 다른 개념이고, 한국어만 있는 이름은 같은 한국어를 쓰는 다른 개념이 함께 있으면 어느 쪽과도 맞추지 않음). 한글이 없는 두 부분 중 하나가 약어면 둘 다 이름입니다(`PTE (Page Table Entry)`). 두 이름 모두 풀어 쓴 이름이 있으면 그 이름이 같아야 하고(같은 약어라도 `SM (Streaming Multiprocessor)`와 `SM (Shared Memory)`는 다른 개념), 한쪽에 풀어 쓴 이름이 없을 때만 세 글자 이상 약어를 머리글자로 맞춥니다(`CPU`와 `Central Processing Unit`). 한국어 부분이 서로 다르면 머리글자나 약어만으로는 맞추지 않습니다. 이때 기존 노트 이름을 그대로 써서 노트를 이어 쓰고 링크합니다(`src/core/conceptNames.ts`). 플러그인이 넣는 링크는 텍스트마다 개념이 처음 나오는 곳 한 번이며, 이름 일부로 찾은 곳은 `[[노트 이름|본문 표기]]`로 겁니다. 한국어 부분은 조사만 붙은 곳에서 찾고 더 긴 낱말이나 합성어 안에서는 찾지 않으며, 코드, HTML, 제목, 대괄호, 수식, 표 구분은 따로 다룹니다. 모델이 다른 이름 순서나 영어 이름만으로 쓴 링크는 기존 개념 노트 이름으로 고칩니다.
- **개념 추출도 같은 방식입니다.**
  - 입력은 해설 본문이 아니라 `gist` 목록, 해설 안의 `[[위키링크]]` 후보, 기존 `Concepts/` 이름 목록입니다.
  - 경량 모델에 low effort로 1회 호출합니다.
- **다시 가져올 때는 바뀐 슬라이드만 생성합니다.** 해시가 같은 슬라이드는 기존 관리 블록을 그대로 씁니다. 1.1.0의 병합 로직에 "생성 생략" 분기를 추가합니다.
  - 주의: 4.7절 해시는 텍스트만 봅니다. 텍스트는 그대로 두고 그림이나 도표만 고친 슬라이드도 해시가 같습니다. 그래서 "해시가 같으면 기존 블록 재사용"을 출시하기 전에 이미지 신호(예: 렌더링 결과의 지각 해시)를 함께 비교해야 합니다.
- **CLI 고정 비용을 줄입니다.** 도구를 최소로 허용하고, 세션을 저장하지 않고, vault 밖 임시 작업 폴더를 씁니다(4.2절 3번).

### 5.5 예산 산정과 가시화
- **실행 전 미리보기.** 가져오기 전에 다음을 보여줍니다.
  - 예상 호출 수와 예상 입력·출력 토큰
  - 이미지를 보내는 슬라이드 수
  - 전처리로 생략한 슬라이드 수
- **모델과 effort에 따른 예상 (2.0.0-beta.5).** 입력 토큰은 같은 프롬프트로 계산하므로 모델과 무관합니다. 출력 토큰(추론 포함)은 effort에 따라 늘려 잡습니다: medium 기준으로 low 0.78배, high 1.3배, xhigh 2.26배, max 2.48배(Claude Code 2.1.291의 effort 비용 지수 low 0.6, medium 0.77, high 1, xhigh 1.74, max 1.91의 비율. Codex도 같다고 봄). effort가 없는 모델(Haiku 4.5)은 1배이고, CLI 기본값은 모델 목록의 기본 단계(Claude Code의 권장 단계, Codex의 default_reasoning_level)로, 모르면 1배로 계산합니다. 프로바이더를 바꾸면 배치를 다시 묶고 그 CLI의 고정 비용으로 계산합니다.
- **실행 후 기록.** CLI의 JSON 출력에서 실제 사용량(입력, 캐시 적중, 출력)을 읽습니다.
  - 노트 frontmatter `alt2obs_usage`에 요약을 남깁니다.
  - 플러그인 데이터에 누적 기록을 남깁니다.
- **상한.** 강의당 토큰 상한을 설정할 수 있습니다. 상한을 넘을 것 같으면 시작 전에 멈추고, 이미지 슬라이드를 줄이는 선택지를 제시합니다.

### 5.6 측정 계획 (1단계 벤치마크)
- **대상**: 60장 안팎 강의 2개와 이미지 위주 강의 1개.
- **비교 대상**: 1.1.0(Gemini 슬라이드별 호출), 2.0 Claude CLI, 2.0 Codex CLI.
- **지표**:
  - 강의당 입력 토큰, 캐시 적중 비율, 출력 토큰
  - 총 소요 시간
  - 품질: 사용자가 무작위 슬라이드 10장을 1~5점으로 평가
- **통과 조건**: 입력 토큰이 1.1.0의 50% 이하이고, 품질 평균이 1.1.0보다 낮지 않아야 합니다.
