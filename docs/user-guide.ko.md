## 시작하기 전에

Alt2Obs는 모델을 직접 부르지 않습니다. 이 컴퓨터에 설치되어 내 계정으로 로그인된 Claude Code CLI나 Codex CLI를 실행합니다. 둘 중 하나를 설치하고 터미널에서 한 번 로그인해 두세요.

```bash
# Claude Code
npm install -g @anthropic-ai/claude-code   # 또는 공식 설치 스크립트
claude                                      # 처음 한 번 실행해 로그인

# Codex
npm install -g @openai/codex
codex login
```

모든 호출은 내 요금제 한도나 API 사용량을 씁니다. 전체 요구 사항은 [README](../README.ko.md#요구-사항)에, 무엇을 어디로 보내는지는 [개인정보와 공개 안내](../README.ko.md#개인정보와-공개-안내)에 있습니다.

### LLM 연결

**LLM 연결** 아래에 **Claude CLI** 카드와 **Codex CLI** 카드가 있습니다.

- 찾은 CLI는 `찾음: <버전>`과 경로가 보입니다. 그 아래 경고가 있으면 시험한 버전보다 오래되었거나, 도움말에 플러그인이 쓰는 옵션이 다 보이지 않는다는 뜻입니다.
- **실행 파일 경로**: 비워 두면 자동으로 찾고, 절대 경로를 넣어도 됩니다.
- **다시 찾기**: 다시 찾습니다.

찾는 방법: Dock이나 시작 메뉴로 실행한 Obsidian은 터미널의 PATH를 모릅니다(nvm 같은 도구는 셸에서 PATH를 정함). 그래서 플러그인은 로그인 셸에서 `command -v claude`를 한 번 실행하고(Windows는 `where`), 흔한 설치 폴더도 살펴봅니다. nvm, Homebrew, `~/.local/bin`, `~/.claude/local`, `~/.npm-global/bin`, `~/.volta/bin`, `~/.bun/bin`, `/usr/local/bin`(Windows는 `%APPDATA%\npm`, `%LOCALAPPDATA%\Programs\claude` 등)입니다. 찾은 실행 파일마다 `--version`과 도움말(`claude --help`, `codex exec --help`)을 확인하며, 모델은 호출하지 않습니다. 플러그인이 쓰는 옵션이 하나라도 없는 실행 파일은 건너뜁니다. 다만 시험한 버전 이상이면 경고와 함께 씁니다. 쓸 수 있는 것 중 가장 새 버전을 저장합니다.

처음 켤 때는 `claude auth status`도 확인합니다. Claude CLI에 로그인되어 있으면 작업에 Claude CLI를 쓰고, 로그인되어 있지 않은데 Codex CLI가 설치되어 있으면 작업을 Codex CLI로 정하고 알림으로 알려 줍니다.

Codex 카드에는 안내가 하나 더 있습니다. Codex는 호출마다 자체 지시문과 `~/.codex/AGENTS.md`가 함께 실려, 플러그인이 줄일 수 있는 만큼 줄인 뒤에도 호출당 약 12k 토큰이 듭니다. 이 비용을 나눠 내려고 Codex는 배치 크기의 두 배로 묶어 보냅니다. 또 읽기 전용 샌드박스라도 Codex는 내 계정이 읽을 수 있는 파일을 읽을 수 있습니다. 프롬프트로 주어진 내용만 쓰라고 지시하지만, 이 점을 감수할 때만 Codex를 고르세요.

**이전 API 키 지우기**는 1.x나 초기 베타에서 저장한 API 키가 `data.json`에 남아 있을 때만 보입니다. 지금은 아무 데서도 쓰지 않고, 이전 버전으로 되돌릴 때를 위해 남겨 둔 값입니다. 버튼을 한 번 더 눌러야 지워집니다.

### 작업별 모델

**작업별 모델** 아래에서 작업마다 프로바이더, 모델, effort를 드롭다운으로 고릅니다.

| 작업 | 쓰는 곳 | 기본값 |
|---|---|---|
| **슬라이드 해설** | 슬라이드별 해설, 전체 요약, 요약 노트의 구간 요약 | Claude CLI, `sonnet`, effort medium |
| **개념 추출** | 개념 노트. 이 작업이 Claude CLI이면 노션 페이지 가져오기에도 씀 | Claude CLI, `haiku`, effort low |
| **전사 정렬 확인** | 불확실한 전사 구간을 한 번 더 확인(선택) | **없음 (스크립트만)** |
| **노트 검증** | 내 노트의 주장 판정 | Claude CLI, `sonnet`, effort medium |

Codex CLI에서는 모델 기본값이 Codex 자체의 기본 모델이고 effort는 같습니다. 줄마다 권장 설정(권장)이 보이고, 한 번 실행하고 나면 CLI가 실제로 쓴 모델(마지막 실행)도 보입니다.

- **모델 목록.** `Opus 5.5 (claude-opus-5-5)`처럼 버전이 붙은 항목은 그 id를 그대로 CLI에 넘겨 늘 같은 모델로 실행합니다. `sonnet` 같은 별칭은 CLI가 그때의 최신 모델로 바꿔 실행하고, 라벨에는 마지막 실행 때 가리킨 모델이 `sonnet (최신 Sonnet, 현재 Sonnet 5.5)`처럼 보입니다. 목록은 Claude Code와 Codex가 디스크에 저장해 둔 모델 목록에서 읽고(모델 호출 없음), 없으면 플러그인에 넣어 둔 목록을 씁니다. **CLI 기본값**은 CLI 자체의 기본 모델을 쓰고, 목록에 없는 모델은 **직접 입력...**으로 넣습니다.
- **effort**(추론 강도). 고른 모델이 지원하는 단계와 이미 저장된 단계만 보입니다(`low`, `medium`, `high`, `xhigh`, `max`, 또는 **effort CLI 기본값**). Haiku 4.5처럼 effort가 없는 모델은 CLI 기본값과 저장된 단계만 보이므로, 개념 추출 기본값 줄에는 `low`가 그대로 보입니다.
- **프리셋**: **절약**은 모든 작업에 경량 모델(Claude는 `haiku`)과 effort low를 씁니다. **품질**은 해설과 검증에 상위 모델(Claude는 `opus`)과 effort high를 쓰고, 개념 추출(그리고 CLI로 정해 둔 경우 전사 정렬 확인)에는 경량 모델과 effort low를 씁니다. 프리셋은 프로바이더를 바꾸지 않고, 표를 직접 고치면 **사용자 지정**이 됩니다.

여기 값은 기본값입니다. 가져오기와 노트 검증을 시작하기 직전에 그 실행에만 쓸 모델로 바꿀 수 있습니다([예상 사용량 패널](#예상-사용량-패널) 참고).

**Notion MCP 조회 도구**는 [Notion MCP 설정](#notion-mcp-설정)에서 설명합니다. 나머지 설정은 [설정 목록](#설정-목록)에 있습니다.

## 강의 가져오기

리본의 책 아이콘(**Alt 강의 가져오기**)을 누르거나 명령 **Open sidebar**를 실행합니다. 사이드바에는 **Alt 노트 목록**, **URL 붙여넣기**, **노트 검증** 탭이 있고, 맨 아래 **최근 가져온 노트**에 최근에 가져온 노트가 보입니다. 명령 **Import lecture note (local list or URL)**도 사이드바를 엽니다.

<p align="center"><img src="assets/screenshot-import.png" alt="강의 종류가 보이는 Alt 노트 목록과 예상 사용량 패널" width="420"></p>

### Alt 노트 목록

위쪽 상태 표시는 플러그인이 Alt에 어떻게 닿는지 보여 줍니다.

- `Alt 연결됨 · 로컬 API`: Alt가 실행 중이고, Alt의 로컬 API로 읽습니다.
- `Alt 꺼짐 · DB 읽기`: Alt 데이터베이스를 복사한 사본을 읽습니다. Alt가 켜져 있어도 로컬 API를 쓸 수 없으면 이렇게 보입니다.
- `연결 안 됨`: 그 아래에 이유가 보입니다.

상태 표시를 누르면 다시 확인합니다. 목록은 Alt 폴더별로 묶여 있고 검색 칸이 있습니다. 강의마다 제목, 상태 칩, 종류 칩, 날짜, 슬라이드 수, 전사 길이가 보입니다.

상태 칩:

- `새 노트`: 아직 가져오지 않음.
- `가져옴`: vault에 노트가 있음.
- `슬라이드 N장 변경`: 가져온 뒤 Alt에서 슬라이드 N장이 바뀜.
- `기존 노트와 연결?`: [기존 노트 연결](#기존-노트-연결) 참고.

종류 칩(칩에 마우스를 올리면 Alt의 노트 종류가 보임):

| 종류 | 뜻 | 버튼 |
|---|---|---|
| `슬라이드` | Alt에 슬라이드 PDF가 있음 | **가져오기** |
| `슬라이드(PDF 첨부)` | 플러그인에서 PDF를 첨부함 | **가져오기**, **Alt 슬라이드로 바꾸기**(Alt에도 슬라이드가 생긴 경우), **첨부 해제** |
| `슬라이드(저장된 PDF)` | Alt에 지금은 슬라이드가 없지만, 예전 가져오기가 슬라이드 노트 옆에 PDF를 저장해 둠 | **가져오기**(그 PDF로) |
| `슬라이드(미첨부)` | Alt에서 "슬라이드"로 만들었지만 아직 슬라이드를 붙이지 않음 | **새로고침**, **PDF 첨부**, **요약 노트 만들기**(전사가 없으면 **강의 노트 만들기**) |
| `노트(전사만)` | Alt에서 "노트"로 만듦: 녹음과 전사만 있음 | **요약 노트 만들기**(기본. 가져온 뒤에는 **요약 노트 다시 만들기**), **PDF 첨부** |
| `노트(전사 없음)` | 슬라이드도 전사도 없음 | **강의 노트 만들기**(Alt 요약과 메모로) |

`슬라이드(미첨부)`는 먼저 Alt에서 슬라이드를 붙인 뒤 **새로고침**을 누르세요. 나머지 두 버튼은 지금 바로 노트를 만들고 싶을 때 씁니다. 슬라이드 파일이 아직 이 컴퓨터에 내려받아지지 않았으면 패널이 그렇다고 알려 줍니다. Alt에서 슬라이드를 한 번 열어 내려받은 뒤 **새로고침**을 누르세요. 이미 가져온 강의에는 **뷰어로 열기**와 **노트 열기**가 더 보이고, **가져오기**는 **다시 가져오기**가 됩니다. `노트(전사 없음)`의 **강의 노트 만들기**도 **다시 가져오기**가 됩니다. 슬라이드 노트가 이미 있는 강의에는 슬라이드 없는 노트를 만드는 버튼이 보이지 않습니다.

목록 아래 **과목**은 노트가 들어갈 과목 폴더입니다. Alt 폴더(`Alt 폴더에서 추정`)나 제목(`제목에서 추정`)에서 추정하거나 기존 노트의 값(`기존 노트`)을 쓰고, 직접 고칠 수 있습니다. 그 아래 줄은 전사를 슬라이드에 맞출지 보여 줍니다. 예를 들어 `전사 타임스탬프 있음 · 슬라이드에 자동 정렬`입니다. 정렬은 스크립트로 하고, 타임스탬프가 있으면 늘 합니다.

슬라이드 PDF가 없는 강의에서 **가져오기**를 누르면 토큰을 쓰기 전에 멈추고 같은 선택지(**요약 노트 만들기**, **PDF 첨부**, **취소**)를 보여 줍니다. 슬라이드 없는 노트로 조용히 넘어가는 일은 없습니다.

### 예상 사용량 패널

아무것도 보내기 전에 **가져오기 전 예상 사용량**이 호출 수, 입력·출력 토큰, 보낼 이미지 수를 보여 주고, 그 아래에 자세한 내용이 이어집니다.

- 만들 슬라이드와 생략한 슬라이드(표지·목차·마무리, 애니메이션 중복, 변경 없음),
- 전사를 얼마나 줄였는지,
- 정렬 결과(`전사 정렬: 슬라이드별 구간 N개`)와 불확실한 구간 수,
- 저장할 핵심 다이어그램, 그리고 첨부한 PDF나 저장된 PDF를 쓸 때는 어떤 PDF인지.

모델 선택 두 개로 이번 실행의 프로바이더, 모델, effort를 바꿀 수 있습니다. **해설·요약 모델**과 **개념 추출 모델**이고, 요약 노트에서는 첫째가 **구간 요약·전체 요약 모델**입니다. 고른 값은 이번 실행에만 쓰고("이번 실행에만 씁니다"), **기본값으로 저장**을 누르면 설정에 남습니다. 예상치는 그 자리에서 다시 계산됩니다.

예상치에서 출력 토큰은 effort에 따라 늘려 잡고(medium 기준), 모델에 따라서는 바꾸지 않으며, 재시도는 넣지 않습니다. 그다음:

- **시작**: 가져오기를 시작합니다.
- **이미지 줄이기**: 슬라이드 이미지를 보낼 때만 보입니다. 텍스트가 있는 도표 슬라이드는 텍스트만 보냅니다.
- **취소**: 아무것도 쓰지 않고 멈춥니다.

예상치가 **강의당 토큰 상한**을 넘으면 패널이 알려 주고 버튼이 **상한 무시하고 시작**으로 바뀝니다. 이 버튼은 한 번 더 눌러야 시작합니다.

### 진행과 취소

진행 중에는 단계(준비, 슬라이드 해설, 전체 요약, 개념 추출, 저장), 묶음 진행률, 실시간 사용량이 보입니다. **취소**를 누르면 저장 전 어느 때든 CLI를 멈추고, 노트는 바뀌지 않습니다. 답이 검사를 통과하지 못한 슬라이드는 한 번 더 요청합니다. **CLI 호출 제한 시간**을 넘긴 호출은 멈추고, 슬라이드 여러 장을 묶은 호출이었다면 반으로 나눠 한 번 더 보냅니다. 8장보다 많이 묶은 호출과 이미지가 든 호출은 제한 시간을 그만큼 늘려 잡습니다. 그래도 실패한 슬라이드는 노트에 예전 해설이 있으면 그것을 남기고, 노트의 `## ⚠️ 처리 실패 슬라이드`에 적힙니다. CLI가 없거나 로그인되어 있지 않을 때, 사용 한도에 걸렸을 때, 호출이 두 번 연속 실패했을 때는 남은 작업을 멈춥니다.

슬라이드 강의는 끝나면 [Synced Viewer](#synced-viewer)로 열립니다.

### 다시 가져오기

다시 가져오면 바뀐 부분만 새로 만듭니다. 텍스트 해시와 이미지 신호가 모두 같은 슬라이드는 기존 해설을 그대로 씁니다(설정 **바뀐 슬라이드만 다시 생성**). 그대로 쓴 해설은 처음 쓰인 문체도 그대로라서, 2.0.2 전에 만든 노트를 다시 가져오면 바뀌지 않은 슬라이드의 예전 "~합니다" 해설과 새로 만든 슬라이드의 "~다" 해설이 섞입니다. 노트 전체를 지금 문체로 바꾸려면 설정에서 **바뀐 슬라이드만 다시 생성**을 끄고 강의를 다시 가져온 뒤 설정을 다시 켜세요. 모든 슬라이드(요약 노트는 모든 구간)를 새로 만들므로 처음 가져올 때만큼 토큰이 들고, 만들지 못한 슬라이드는 이전 해설을 그대로 둡니다. 노트를 쓰기 전에 **기존 노트 업데이트** 창이 추가·제거된 섹션과 개념, 슬라이드 변경을 보여 줍니다. **업데이트**나 **취소**를 누르세요.

기존 슬라이드의 절반을 넘게 새 슬라이드와 맞지 않으면 다른 강의를 이 노트에 덮어쓰려는 것일 수 있습니다. 이때는 확인란에 표시해야 업데이트할 수 있고, 맞지 않는 슬라이드의 메모는 노트 끝 `## 🗑️ 삭제된 슬라이드 (orphan)`로 옮겨집니다.

### 기존 노트 연결

1.x나 공유 링크로 만든 노트는 Alt의 공개 id만 압니다. 이런 노트가 Alt 목록의 강의와 아래 조건에 맞으면 그 강의에 `기존 노트와 연결?`이 보입니다.

- 노트 제목이 강의 제목이나 슬라이드 파일 이름과 같음(대소문자, 띄어쓰기, 문장 부호는 무시)
- 노트에 기록된 Alt 날짜와 강의 날짜가 하루 넘게 차이 나지 않음(어느 한쪽 날짜를 모르면 날짜는 따지지 않음)

노트 경로 옆 **연결**을 누르고 확인하면, 그 노트 frontmatter에 `alt_local_id`만 넣고 나머지는 바꾸지 않습니다. 그 뒤로는 가져오기가 그 노트를 업데이트하고 메모도 지킵니다. 자동으로 연결하지는 않으며, 제목이 같은 다른 강의 노트가 있으면 새 노트의 파일 이름에 강의 날짜를 붙입니다.

### 공유 링크로 가져오기

이 컴퓨터의 Alt 앱에 없는 강의(다른 컴퓨터의 노트나 공유받은 노트)는 **URL 붙여넣기** 탭을 씁니다.

### 관리 표식과 메모

- `<!-- alt2obs:... -->` 줄은 플러그인이 관리하는 블록의 표식입니다. 다시 가져오면 `start`와 `end` 사이만 바꾸고, 해시로 슬라이드마다 메모 자리를 찾습니다. 이 줄은 지우지 마세요.

- 슬라이드 해시는 정규화한 슬라이드 텍스트의 SHA-1 앞 8자리이고, 페이지 번호는 넣지 않습니다. 그래서 슬라이드를 끼워 넣거나 지우거나 순서를 바꿔도 메모가 자기 슬라이드를 따라갑니다. 텍스트가 없는 페이지만 노트 id와 페이지 번호로 정합니다.
- 사라진 슬라이드의 메모는 `## 🗑️ 삭제된 슬라이드 (orphan)`로, 요약 노트에서 사라진 구간의 메모는 `## 🗑️ 사라진 구간 (orphan)`으로 옮깁니다. 두 구간이 하나로 합쳐지면 다른 쪽 메모는 `이전 구간 N [..]의 메모` 표시와 함께 합쳐진 구간 아래에 붙습니다.

## Synced Viewer

Synced Viewer는 슬라이드 PDF와 강의 노트를 나란히 보여 주고 함께 스크롤합니다.

<p align="center"><img src="assets/screenshot-viewer.png" alt="전사 패널을 연 Synced Viewer" width="800"></p>

여는 방법:

- 슬라이드 강의를 가져오면 열립니다(열려 있는 뷰어 탭이 있으면 그 탭을 씀).
- 사이드바에서 가져온 강의의 **뷰어로 열기**.
- 강의 노트나 그 PDF를 연 상태에서 명령 **Open synced viewer (PDF + lecture .md)**.
- **강의 PDF를 열면 뷰어로 열기**(기본 켬)가 켜져 있을 때 파일 탐색기나 링크로 강의 PDF를 열기. 강의 PDF는 같은 폴더에 같은 이름의 강의 노트가 있는 PDF입니다. 그 강의의 뷰어가 이미 열려 있으면 그 탭을 보여 줍니다. 강의 노트(`.md`)를 여는 것은 바뀌지 않습니다.

툴바: **◀ 이전**, **다음 ▶**(이전·다음 슬라이드), 확대·축소 버튼, **📝 노트 편집**, **PDF만 보기**, 그리고 페이지 번호. 뷰어 안의 노트 창은 읽기 전용입니다. **📝 노트 편집**을 누르면 뷰어 옆에 일반 편집기로 노트가 열리고, 고치는 대로 뷰어에 반영됩니다. **PDF만 보기**는 Obsidian 자체 PDF 보기(찾기, 선택, 주석)로 열고, 그 탭은 뷰어로 바뀌지 않습니다. Obsidian을 켤 때나 이 설정을 켤 때 이미 열려 있던 PDF 탭도 PDF로 남습니다.

어느 쪽을 스크롤해도 다른 쪽이 같은 슬라이드로 따라옵니다. 노트 창의 `[[위키링크]]`를 누르면 그 노트가 열리고, Cmd-클릭(Windows와 Linux는 Ctrl-클릭)하면 새 탭에서 열립니다.

**전사 패널.** `alt_alignment`가 있는 노트는 툴바에 `정렬 기준 동기화 · 전사 매칭`과 **전사 패널** 버튼이 보입니다. 패널은 지금 슬라이드 구간의 전사를 `[mm:ss]` 시각과 함께 보여 주고, 맞춤이 약하면 `(정렬 불확실)`이라고 표시합니다. 전사는 vault 밖 OS 캐시 폴더에 두며, 거기 없으면 Alt에서 다시 읽으므로 Alt에 닿을 수 있어야 합니다.

슬라이드 없는 노트에는 뷰어가 없습니다. **뷰어로 열기**를 누르면 이유를 알려 주고 **PDF 첨부**를 제안합니다.

## 슬라이드 없는 강의

Alt 강의 중에는 녹음과 전사만 있는 것이 많습니다. 전사로 요약 노트를 만들거나, 슬라이드 PDF를 첨부해 다른 슬라이드 강의와 똑같이 가져올 수 있습니다.

### 전사로 요약 노트 만들기

**요약 노트 만들기**는 전사를 말한 시간 기준 9~15분(약 12분) 구간으로 나누되, 주제가 바뀌는 곳에서 자릅니다. 1분 넘게 쉰 시간은 1분으로 셉니다. 스크립트로 나누므로 토큰이 들지 않고, 2시간 강의는 8~10구간이 됩니다. 구간마다 불릿 요약을 만들고(필요한 곳에만 정의·예시 콜아웃) 항목마다 `[mm:ss]` 시각을 붙이며, 전체 요약과 개념 노트는 구간 요지로 만듭니다. 2시간 강의도 구간 요약, 전체 요약, 개념 추출 3번 호출로 끝납니다. 예상 사용량, 진행, 취소, 사용량 기록, 모델 고르기는 슬라이드 강의와 같습니다.

다시 가져오면 전사가 바뀌지 않은 구간은 호출 없이 요약을 그대로 쓰고, 메모는 자기 구간에 남습니다.

한계: 요약의 질은 음성 인식 결과를 넘지 못합니다. 공유 링크로 가져온 전사에는 시각이 없어 구간을 글자 수로 나누고, 구간에 시각이 없으며, 그 노트는 노트 검증에 쓸 수 없습니다. **요약 노트 만들기**를 고르면 노트 옆에 PDF가 있어도 쓰지 않고, 이미 슬라이드 노트가 있는 강의를 요약 노트로 바꾸지는 않습니다.

### PDF 첨부

**PDF 첨부**는 `노트(전사만)`, `슬라이드(미첨부)` 강의의 사이드바 버튼, 멈춘 가져오기의 선택 창, 그리고 명령 **Attach lecture PDF to the current lecture note**(강의 노트나 그 PDF를 연 상태)에 있습니다.

1. **강의 PDF 첨부** 창에서 **보관함에서 고르기**(검색해서 고르기)나 **컴퓨터에서 고르기**를 누릅니다.
2. PDF를 강의 노트 옆 `<과목>/Lectures/<강의>.pdf`로 복사하고, 노트 frontmatter에 `alt_pdf_source: "attached"`를 넣습니다. 300 MB가 넘는 파일과 PDF가 아닌 파일은 받지 않습니다.
3. Alt 노트 목록에서 그 강의를 다시 가져옵니다. 이제 슬라이드 강의로 다뤄집니다: 슬라이드별 해설, 전사 정렬, Synced Viewer, 슬라이드 대조 검증.

이미 요약 노트가 있는 강의는 슬라이드 노트로 바뀌고, 예전 요약 노트 전체와 내 메모는 노트 끝 `## 이전 노트 백업`에 남습니다.

첨부한 PDF는 Alt의 PDF보다 먼저 쓰고, 예상 사용량에 그렇게 적습니다. 나중에 그 강의에 Alt 슬라이드가 생기면 패널에 보이고, **Alt 슬라이드로 바꾸기**를 누르면 `alt_pdf_source` 줄을 지워 다음 가져오기부터 Alt의 PDF를 씁니다. **첨부 해제**는 이 표시를 지웁니다.

첨부한 파일은 이렇게 다룹니다. 플러그인이 만든 사본이고 그 뒤 바뀌지 않은 파일만, Obsidian에서 정한 파일 삭제 방식대로 지웁니다. 기본은 시스템 휴지통이고, Obsidian 설정에서 vault의 `.trash` 폴더나 영구 삭제로 정해 두었다면 그 방식을 따릅니다. 사본인지는 만들 때 기록한 크기와 SHA-1로 알아보고, 파일 이름을 바꾸거나 옮겨도 기록이 따라갑니다. 그 밖의 파일(노트 옆에 원래 있던 vault PDF를 그대로 첨부한 경우, 내가 옮겨 온 파일, 내가 고친 사본)은 지우지 않습니다. 첨부 해제는 파일을 그대로 두고, Alt 슬라이드로 바꾸기는 Alt의 PDF가 덮어쓰지 않도록 `<강의> (첨부한 PDF).pdf`(그 이름이 있으면 번호를 붙임)로 이름을 바꿉니다. 확인 창에서 어느 경우인지 알려 줍니다.

## 노트 검증

**노트 검증** 탭은 내가 쓴 노트를 강의 슬라이드와 전사에 대조합니다. 근거는 스크립트가 찾고, 모델은 판정만 합니다. 내 노트는 바꾸지 않습니다.

<p align="center"><img src="assets/screenshot-verify.png" alt="검증을 마친 노트 검증 탭과 판정별 개수" width="420"></p>

### 입력

**입력**에서 하나를 고릅니다.

- **보관함 파일**: vault의 노트. 예를 들어 노션 페이지를 마크다운으로 내보내 vault에 넣은 파일.
- **Notion MCP**: 노션 페이지 URL을 넣고 **가져오기**를 누르면 내 Claude Code의 Notion MCP로 가져옵니다(호출 1회, 가져오는 중에는 같은 버튼으로 취소). [Notion MCP 설정](#notion-mcp-설정)을 참고하세요.
- **붙여넣기**.

그다음 **대상 강의**를 고릅니다. 가져온 강의 노트가 모두 보이고, 요약 노트에는 `(전사 요약)`이 붙습니다.

### 실행

1. **예상 사용량 보기**를 누릅니다. **검증 전 예상 사용량** 패널에 주장 몇 개가 판정 몇 개가 되는지(`주장 N개 → 판정 M개`), 근거 검색에 토큰이 들지 않는다는 것, 누락 확인, 예상 호출과 토큰이 나옵니다. **판정 모델**로 이번 검증의 모델을 바꿀 수 있습니다.
2. **검증 실행**을 누릅니다. 그만두려면 **취소**.
3. 끝나면 판정별 개수와 **결과 노트 열기**가 보입니다.

판정은 `맞음`, `틀림`, `근거 없음`, `전사 불확실`(음성 인식 오류가 의심됨), 그리고 `누락 후보`(어떤 주장도 다루지 않은 슬라이드)입니다.

동작 방식: 노트를 문장과 불릿 단위의 주장으로 나눕니다. 주장마다 스크립트가 용어 겹침으로 슬라이드 상위 2개와 정렬된 전사 구간 상위 2개를 찾습니다. 한국어 전공 용어를 영어로 잇는 내장 용어표도 써서, 한국어 노트도 영어 슬라이드와 맞출 수 있습니다. 슬라이드와 용어가 하나만 겹치는 주장은 `겹치는 용어 1개`로 표시합니다. 직접 맞는 근거가 없는 주장은 가까운 주장과 절 제목에서 후보를 빌려 옵니다(`(문맥 근거)`). 어떤 후보도 없는 주장은 판정하지 않고 `용어 불일치로 근거 검색 실패` 절에 따로 적으며, 그런 주장이 30%를 넘으면 시작 전에 경고합니다. 모델은 호출 한 번에 주장 20개씩 판정합니다. 어떤 주장과도 이어지지 않은 슬라이드는 제목과 핵심 문장만 한 번 더 보내 누락 후보를 고릅니다.

결과는 `Verification/<강의> verification.md`에 저장됩니다. 주장마다 인용, 판정, 이유, 그리고 `[[...#📚 슬라이드 12|<강의> · 슬라이드 12]]` 같은 근거 링크와 전사 시각 `[mm:ss]`가 담긴 카드가 있습니다. 다시 실행해도 결과 노트의 `## 내 메모` 아래에 쓴 글은 그대로 둡니다.

요약 노트는 전사 구간이 근거이고, 링크는 `⏱ 구간 N`을 가리킵니다. 근거가 음성 인식뿐이라 깨진 문장은 `전사 불확실`로 나오기 쉽습니다. 공유 링크로 만든 요약 노트는 시각이 없어 검증할 수 없습니다.

### Notion MCP 설정

1. 터미널에서 Claude Code에 Notion MCP 서버를 추가합니다.

   ```bash
   claude mcp add --transport http notion https://mcp.notion.com/mcp
   ```

2. `claude`를 실행하고 `/mcp`에서 Notion에 로그인합니다.

플러그인은 `claude mcp list`와 `claude mcp get`으로 서버를 찾습니다(모델 호출 없음). `claude mcp list`는 Claude Code에 설정된 MCP 서버를 모두 연결 확인하므로, 로컬 서버를 실행하거나 원격 서버에 접속할 수 있습니다.

가져오기 호출은 Notion 조회 도구 하나만 쓰게 제한합니다. 내장 도구는 끄고, Notion의 나머지 도구(페이지 만들기, 고치기 등)는 이름으로 막으며, 사용자 설정과 hook이 끼어들지 않게 합니다. 호출이 어떤 서버를 켜는지는 Notion을 연결한 방식에 따라 다릅니다.

- 직접 추가한 Notion 서버가 `https` 주소(http나 sse, 헤더 없음)이면 그 서버 하나만 켭니다.
- Claude Code 플러그인이 제공하는 서버는 그 플러그인의 `.mcp.json`이나 `.claude-plugin/plugin.json`에 그런 주소가 있으면 그 서버 하나만 켭니다. 아니면 그 플러그인을 켜 둔 내 사용자 설정을 쓰되, hook은 끄고 다른 MCP 서버는 모두 막습니다.
- claude.ai 커넥터, 그리고 따로 넘길 수 없는 직접 추가한 서버(로컬 명령이거나 헤더가 있는 서버)는 내 MCP 목록을 쓰되 다른 서버를 모두 막습니다.

내 MCP 목록이나 사용자 설정을 쓸 때도 Claude Code는 다른 MCP 서버를 실행합니다. 막히는 것은 그 서버들의 도구입니다.

페이지 내용은 모델이 옮겨 적은 글이 아니라 조회 도구의 결과 그대로이고, 그 호출의 도구 결과로 Anthropic에도 전달됩니다. vault 밖에 페이지의 마지막 수정 시각과 함께 저장하고, 지난번과 같은 페이지면 패널이 알려 줍니다. 페이지가 길어 결과가 잘리면 경고합니다. Claude Code가 큰 결과를 `~/.claude/projects/**/tool-results/` 아래 파일로 저장했다면 거기서 전체를 읽습니다. 그 파일은 지우지 않습니다.

가져오기에는 개념 추출 작업이 Claude CLI이면 그 모델을, 아니면 CLI 기본 모델을 effort low로 씁니다. 서버 이름이 다르면 **Notion MCP 조회 도구**에 `mcp__<서버>__notion-fetch` 형식으로 도구 이름을 넣으세요. Notion MCP가 없으면 패널이 이 설정 방법을 보여 주고 **보관함 파일로 검증**을 제안합니다.

## 이전 버전에서 옮기기

### 1.x 폴더 구조 옮기기

1.x는 강의 노트를 과목 폴더 바로 아래에 두었습니다. 명령 팔레트에서 **Migrate 1.x vault layout**을 실행하세요.

1. **1.x 폴더 구조 옮기기** 창이 `Lectures/`로 옮길 강의 노트와 그 PDF 목록을 먼저 보여 줍니다.
2. **옮기기 (N개)**를 누릅니다. Obsidian의 이름 바꾸기로 옮기므로 그 파일을 가리키는 링크도 함께 바뀝니다.

지우거나 덮어쓰는 파일은 없습니다. 옮길 자리에 같은 이름의 파일이 있으면 건너뛰고 목록에 보여 줍니다. `Concepts/`는 그대로이고, `Exam/`의 예전 시험 요약과 강의 노트가 아닌 내 노트는 건드리지 않습니다. 다시 실행해도 이미 옮긴 파일은 그대로입니다.

1.x 노트를 처음 다시 가져오면 2.0에서 슬라이드 해시 방식이 바뀌어 모든 슬라이드가 한 번 바뀐 것으로 나옵니다. 메모는 그대로 남습니다.

### 1.x나 2.0.0 베타에서

새 버전을 예전 버전 위에 설치하면 됩니다. id와 폴더(`alt2obsidian`)가 같아 그 자리에서 업데이트되고 설정, 기록, 단축키, 열린 탭이 그대로입니다. 1.x나 초기 베타에서 올리면, 처음 켤 때 없어진 Gemini API나 Ollama를 쓰던 작업을 로그인된 Claude CLI(없으면 설치된 Codex CLI)로 옮기고, 비어 있던 모델과 effort를 작업 기본값으로 채운 뒤 바뀐 내용을 알림으로 보여 줍니다. Ollama를 쓰던 작업이라면 이제 슬라이드 텍스트와 전사가 클라우드 모델로 갑니다. 예전 `alt2obsidian-*` 클래스로 쓴 CSS 스니펫은 `alt-to-obs-*`로 고쳐야 합니다. 1.x의 Gemini 방식이 필요하면 [1.1.0](https://github.com/BiQnT/alt2obsidian/releases/tag/1.1.0)을 쓰세요.

### 2.0.0(id `alt-to-obs`)에서 옮기기

2.0.0만 id `alt-to-obs`로 나왔고, 2.0.1부터 다시 `alt2obsidian`을 씁니다. Obsidian은 둘을 서로 다른 플러그인으로 보고, 목록에는 둘 다 "Alt2Obs"로 나옵니다(버전으로 구별).

1. 새 버전을 설치합니다(폴더 `.obsidian/plugins/alt2obsidian/`). `alt-to-obs` 폴더는 그대로 두세요. 새 버전을 켜기 전에 지우면 설정을 가져올 수 없습니다.
2. **설정 → 커뮤니티 플러그인**에서 버전이 2.0.0인 Alt2Obs를 끕니다. 아직 삭제하지는 않습니다.
3. 새 Alt2Obs를 켭니다. 2.0.0의 설정과 기록(CLI 경로, 사용량, 최근 노트, 첨부 기록. 예전 API 키는 빼고)을 가져왔다는 알림이 뜹니다. **설정 → Alt2Obs**에서 저장 폴더, LLM 연결, 작업별 모델이 예전과 같은지 확인하세요.
4. 버전이 2.0.0인 Alt2Obs를 삭제합니다. 노트와 폴더는 그대로입니다.
5. 2.0.0 명령에 단축키를 지정했다면 다시 지정합니다.

자세한 동작:

- 2.0.0이 아직 켜져 있으면 켤 때마다 경고하고, 그동안은 두 플러그인 모두 강의 PDF를 뷰어로 바꾸지 않습니다. 2.0.0이 "Alt2Obsidian"을 끄고 삭제하라고 알리면 새 버전을 가리키는 것이니 따르지 마세요.
- 새 버전 폴더의 `data.json`이 2.0.0의 것보다 나중에 바뀌었다면(2.0.0 뒤에 1.x나 베타를 다시 쓴 경우) 그 데이터를 그대로 쓰고, 가져오지 않은 파일을 한 번 알려 줍니다. 그래도 가져오려면 명령 **Import settings from version 2.0.0 (alt-to-obs)**를 실행하세요(확인 후 가져옴).
- 2.0.0의 `data.json`을 읽지 못하면 알리고, 읽힐 때까지 켤 때마다 다시 시도합니다.
- 2.0.0이 꺼져 있으면, 2.0.0이 남긴 탭을 새 버전의 뷰로 다시 엽니다.

## 설정 목록

Obsidian 1.13 이상에서는 이 탭을 설정 정의로 그려서, 이 플러그인의 설정이 Obsidian 설정 검색에 나옵니다. model, effort, folder, Claude, Codex, Notion 같은 영어 단어로도 찾을 수 있습니다. 이때 숫자 칸은 Enter를 누르거나 칸을 벗어날 때 저장되고, Esc를 누르면 원래 값으로 돌아갑니다. 최솟값보다 작거나 소수인 값은 설정 아래에 오류를 띄우고 저장하지 않으며, 칸을 비우면 기본값으로 돌아갑니다. 1.13보다 낮은 버전에서는 이전 화면이 나옵니다. 숫자 칸은 한 글자 칠 때마다 저장되고, 비었거나 잘못된 값(숫자가 아니거나 최솟값보다 작은 값)은 저장하지 않습니다. 그래서 칸이 비어 있거나 입력한 값이 보여도 저장된 값은 예전 그대로입니다. 소수는 소수점 아래를 버리고 저장합니다.

## 문제 해결

**"claude CLI를 찾지 못했습니다".** Dock이나 시작 메뉴로 실행한 Obsidian은 터미널의 PATH를 모릅니다. 터미널에서 `command -v claude`(Windows는 `where claude`)를 실행해 나온 절대 경로를 CLI 카드의 **실행 파일 경로**에 넣거나 **다시 찾기**를 누르세요. `codex`도 같습니다.

**CLI가 오래되었을 때.** 플러그인이 쓰는 옵션은 Claude Code 2.1.283, Codex 0.155.1(시험한 버전)에서 확인했습니다. 이보다 오래된 CLI도 도움말에 플러그인이 쓰는 옵션이 모두 있으면 그대로 쓰고, 카드에 경고만 보여 줍니다. 옵션이 빠진 실행 파일은 시험한 버전 이상이 아니면 쓰지 않으며, 찾은 실행 파일마다 경로, 버전, 없는 옵션을 알려 줍니다. `claude update`나 `npm i -g`로 업데이트하거나 새 버전의 경로를 넣으세요. 실행 중에 모르는 옵션이라는 오류가 나도 CLI를 업데이트하면 됩니다.

**"Claude Code나 Codex CLI가 필요합니다".** 처음 켤 때 로그인된 Claude CLI도, 설치된 Codex CLI도 찾지 못한 경우입니다. 하나를 설치하고 로그인한 뒤 **LLM 연결**에서 **다시 찾기**를 누르세요.

**Alt가 `연결 안 됨`일 때.** 상태 표시 아래에 이유가 보입니다.

- Alt가 꺼져 있고 데이터베이스도 읽지 못함: Alt를 켜고 상태 표시를 누르세요.
- `Alt 설정에서 로컬 HTTP 서버가 꺼져 있습니다`: Alt 설정에서 로컬 HTTP 서버를 켜세요.
- 토큰 파일을 읽지 못하거나 Alt가 토큰을 거부함: Alt를 다시 시작한 뒤 새로고침하세요.
- Alt 포트의 프로그램이 Alt인지 확인하지 못함: 토큰을 보내지 않고 데이터베이스 사본을 대신 읽습니다.
- Alt가 꺼져 있을 때 데이터베이스를 읽으려면 Obsidian에 들어 있는 Node의 내장 SQLite(`node:sqlite`, Node 22.13 이상)가 필요합니다. 개발자 콘솔(Ctrl+Shift+I, macOS는 Cmd+Option+I)을 열고 `process.versions.node`를 입력하면 버전을 볼 수 있습니다. 오래된 Obsidian 설치본에는 없으니 Obsidian을 최신으로 설치하거나 Alt를 켜세요.
- `알 수 없는 Alt 데이터베이스 스키마`: Alt를 켜서 로컬 API로 가져오세요.
- Alt 데이터가 다른 곳에 있음: **Alt 데이터 폴더**를 지정하세요.

**슬라이드 PDF가 이 컴퓨터에 없을 때.** 다른 곳에서 Alt에 동기화된 슬라이드 파일은 아직 이 컴퓨터에 내려받아지지 않았을 수 있습니다. Alt에서 슬라이드를 한 번 연 뒤 **새로고침**을 누르세요. Alt가 켜져 있어도 동기화된 슬라이드 파일은 Alt 데이터베이스 사본으로 찾으므로, 이때도 `node:sqlite`가 필요합니다(위 항목 참고).

**토큰 상한을 넘어 시작하지 않거나 사용 한도에서 멈출 때.** 토큰 상한은 가져오기를 시작하기 전에 예상치와 비교할 뿐이고, 이미 시작한 가져오기를 상한에서 멈추지는 않습니다. effort를 낮추거나, **이미지 줄이기**를 쓰거나, **강의당 토큰 상한**을 올리거나, 요금제 한도가 풀릴 때까지 기다리세요.

**강의 PDF가 일반 PDF로 열릴 때.** PDF가 같은 폴더에 같은 이름의 강의 노트와 함께 있어야 하고, **강의 PDF를 열면 뷰어로 열기**가 켜져 있어야 합니다. Obsidian을 켤 때 열려 있던 탭과 **PDF만 보기**로 연 탭은 PDF로 남습니다. Alt2Obs 2.0.0도 켜져 있는 동안에는 어떤 PDF도 뷰어로 바뀌지 않습니다.

**어떤 줄에 입력이 안 될 때.** 감춘 관리 주석 줄입니다. 소스 모드로 바꾸면 보이고, **관리 주석 숨기기**를 꺼도 됩니다.

**Windows.** CLI는 `where`로 찾고, 못 찾으면 `%APPDATA%\npm`, `%USERPROFILE%\.local\bin`, `%LOCALAPPDATA%\Programs\claude` 같은 폴더를 살펴봅니다. npm으로 설치한 `claude.cmd`, `codex.cmd`는 셸 없이 실행하려고 그 안의 JavaScript 파일을 `node.exe`로 직접 실행하므로, `node.exe`가 PATH나 같은 폴더에 있어야 합니다. 네이티브 설치본 `claude.exe`는 그대로 실행합니다. 취소하면 `taskkill /T /F`로 프로세스 트리를 끝냅니다. `where`는 콘솔 코드 페이지로 경로를 출력해서 사용자 이름에 한글 같은 비ASCII 문자가 있으면 결과가 깨질 수 있는데, 그때는 폴더 탐색이 대신 찾습니다. Windows는 아직 단위 테스트로만 확인했습니다.

## FAQ

**Alt 앱이 꼭 있어야 하나요?** 강의 목록을 쓰려면 같은 컴퓨터에 있어야 합니다. 없으면 공개 Alt 공유 링크로 가져올 수 있지만 전사 시각은 없습니다.

**돈이 드나요?** 플러그인은 무료입니다. 호출마다 내 Claude나 ChatGPT 요금제, 또는 API 사용량을 씁니다. 실행 전에 예상 사용량 패널이 예상 호출과 토큰을 보여 주고, 실제로 쓴 양은 노트에 남습니다.

**어떤 모델을 골라야 하나요?** 기본값부터 쓰세요. 해설과 검증은 `sonnet`에 effort medium, 개념 추출은 `haiku`에 effort low입니다. **절약**은 모든 작업을 경량 모델과 effort low로, **품질**은 해설과 검증을 상위 모델과 effort high로 바꿔 비용이 더 들고, 개념 추출은 경량 모델과 effort low로 둡니다. 차이는 시작 전 예상 사용량 패널에서 볼 수 있습니다.

**만들어진 해설을 고쳐도 되나요?** 고칠 수는 있지만, 관리 블록 안의 글은 그 슬라이드가 바뀌어 새로 만들 때 바뀝니다. 내 글은 `> [!note] 내 메모`나 관리 블록 밖에 쓰세요.

**`<!-- alt2obs ... -->` 줄을 지워도 되나요?** 지우지 마세요. 다시 가져올 때 이 줄로 메모를 맞는 슬라이드에 둡니다.

**시험 요약과 Gemini는 어디 갔나요?** 시험 요약은 Alt의 퀴즈·플래시카드 플러그인과 겹쳐 2.0에서 없앴고, 예전 `Exam/` 파일은 그대로 남습니다. Gemini API와 Ollama 지원은 2.0.0-beta.4에서 없앴습니다. 필요하면 [1.1.0](https://github.com/BiQnT/alt2obsidian/releases/tag/1.1.0)을 쓰세요.

**모바일에서도 되나요?** 안 됩니다. 데스크톱 CLI를 실행하므로 데스크톱 전용입니다.

**Obsidian 없이 가져올 수 있나요?** 이 저장소의 `/alt2obs` Claude Code 스킬이 Claude Code 세션에서 같은 프롬프트, 도움 스크립트, 노트 형식으로 강의를 가져옵니다. [scripts/phase2/README.md](../scripts/phase2/README.md)(영어)를 참고하세요.

## 확인한 버전과 알려진 한계

| 항목 | 버전 |
|---|---|
| OS | macOS (Windows, Linux는 단위 테스트만) |
| Obsidian 최소 버전 | 1.7.2 (1.13 이상이면 설정 검색 같은 Obsidian 1.13 API도 씀) |
| Obsidian | 앱 코드 1.14.4, 설치본 1.12.4 |
| Alt | 0.14.0 (로컬 데이터베이스), 0.12.0 (로컬 API) |
| Claude Code CLI | 2.1.291 (2.1.283보다 오래되면 카드에 경고) |
| Codex CLI | 0.155.1 (이보다 오래되면 카드에 경고) |

알려진 한계:

- **요약 노트**는 음성 인식 결과로만 만들어서, 말이 적거나 잘못 알아들은 구간은 요약도 비거나 틀릴 수 있습니다. PDF 첨부의 파일 고르기 창과 사이드바 버튼은 아직 실제 Obsidian 창에서 확인하지 않았습니다.
- **Windows, Linux**는 실제 PC에서 확인하지 않았습니다. Windows의 CLI 실행(`where`, npm `.cmd`, `taskkill`)과 Alt 소유 확인(`netstat`, `tasklist`)은 단위 테스트로 확인했습니다.
- **2.0.1의 id 되돌림**(2.0.0 데이터 가져오기, 두 플러그인이 함께 켜졌을 때의 경고, 2.0.0 탭 다시 열기)과 `main.js`에 넣은 PDF.js 워커는 가짜 vault와 헤드리스 Chromium 테스트로 확인했고, 실제 Obsidian 창에서는 아직입니다.
- **Notion MCP**는 직접 추가한 Notion 서버만 실제 호출로 확인했습니다. claude.ai 커넥터와 Claude Code 플러그인이 제공하는 서버는 가짜 CLI 테스트로만 확인했습니다.
- **전사 정렬 정확도**(강의 2개에서 80.4%와 62.9%, 균등 분할은 9.9%와 3.0%)는 초안 라벨 기준이고, 라벨 확인이 남아 있습니다.
- **토큰**: 141분, 46장 강의 기준 Claude CLI 예상 입력은 약 7.3만 토큰으로, 1.1.0 Gemini 방식 예상치(약 10.8만)의 68%입니다. 실측 벤치마크는 아직입니다.
